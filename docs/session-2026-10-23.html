2 · The browser harness, and the flake

The gated harness (PITCHFRAME_BROWSER=1 python -m unittest tests.test_browser_harness, 13 tests) failed its analyst-column wheel check twice — “the wheel over the column does not scroll it” — then passed twice on identical code. Diagnosis: the probe dispatched one CDP mouseWheel turn and read scrollTop one fixed sleep later, racing the browser's scroll scheduler. The refactors under test were exonerated by the unit suites in any case.

The fix keeps the assertion about the page and drops the only thing that was ever timing: the gesture repeats until the page answers, and the answer is polled with the harness's own waitFor helper rather than timed. After the fix, three consecutive 13/13 green runs where the old probe failed two of four.

4 · Proposed, awaiting approval: the ledger's copy

The ledger sentence is asymmetric in a way that shows: the accepted branch goes through the shared plural (“1 line published…”, “2 lines published…”), while the rejected branch passes "lines" pre-pluralised — preserved verbatim by commit 186aa37 on purpose. That preservation has a consequence: with verified = 1 and any rejections, the page prints “1 lines published” — a grammatical wart, not just an asymmetry.

Proposed copy (recommended) 
ledger.rejected
  ? `${plural(ledger.verified, "line")} published, ${plural(ledger.rejected, "claim")} caught by measurement and corrected.`
  : `${plural(ledger.verified, "line")} published, each one checked against the event stream.`

One-word change (“lines” → passed through plural as "line"). Kills the “1 lines” wart; every other word is untouched, so the existing wording tests hold.

Alternatives, if a different register is wanted:

  • Collective “lines” kept — reword the accepted branch to match (“…published, each one checked…”, plural always), accepting “1 lines” in the rare one-line-and-rejected case. Not recommended: it keeps the wart.
  • Restructure both branches so they read parallel (“N lines published; M caught and corrected.”). Cleaner copy, but a larger wording change than the session's rule — “this extraction changes wording nowhere” — allows.

Nothing has been edited or committed for this yet; it waits for approval.
